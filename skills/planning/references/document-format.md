# 계획 문서 표현

계획의 구조·비교·흐름을 빠르게 이해해야 할 때 적용한다. 문서 형식 자체가 목표가 되지 않게 하고 필요한 표현만 선택한다.

## 기본 형식

- 한글 섹션명을 우선한다. 기존 문서 스타일이나 사용자 요청이 다르면 그 형식을 따른다.
- 큰 섹션은 `##`, 작업 단위는 `###`를 사용한다.
- 순서가 중요한 작업은 단계 번호를 사용하고 독립 작업은 필요하면 `(독립)`을 표시한다.
- 변경 대상 비교는 표, 파일·폴더·UI 계층은 텍스트 트리, 관계와 동적 흐름은 Mermaid를 우선 검토한다.

## 구조 트리

```text
Root/
├── ExistingArea/                    ← 기존
│   ├── ExistingItem                 ← 수정
│   └── NewItem                      ← 신규
├── MovedArea/                       ← 이동
│   └── MovedItem                    ← 이동
└── RemovedArea/                     ← 삭제 또는 통합
```

기존 항목 전체를 나열하지 않으면 `(기존 항목들)` 또는 `...`처럼 생략을 명시한다.
확인하지 않은 위치나 관계를 확정 구조처럼 표시하지 않는다.

## 표

변경 대상이 적거나 전후 비교가 핵심이면 표를 사용한다.

```markdown
| 대상 | 작업 | 내용 |
|---|---|---|
| `기존 대상` | 수정 | 책임 정리 |
| `신규 대상` | 신규 | 새 진입점 |
| `통합 대상` | 삭제 | 신규 대상에 흡수 |
```

## Mermaid

글이나 트리보다 관계와 흐름이 분명해질 때만 사용한다.

- `flowchart`: 컴포넌트 관계, 데이터 흐름, 조건 분기
- `sequenceDiagram`: 호출과 상호작용 순서
- `classDiagram`: 타입과 인터페이스의 구조적 관계
- `stateDiagram-v2`: 상태와 상태 전이

단순 파일 구조는 텍스트 트리를, 단순 목록과 비교는 표를 우선한다.
확인된 현재 구조, 목표 구조와 신규·수정·이동 대상을 구분하고 추측을 사실처럼 다이어그램에 넣지 않는다.
