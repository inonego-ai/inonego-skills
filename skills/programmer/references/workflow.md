
# 워크플로우

프로그래밍 작업을 작업 유형에 따라 필요한 워크플로우

---

## 1. 워크플로우 레퍼런스

각 워크플로우 레퍼런스는 **해당 단계에 진입할 때** 로드한다.  
미리 전부 로드하지 않는다.

각각 `${CLAUDE_PLUGIN_ROOT}/skills/programmer/references/workflows/`에 위치한다.

- [설계](design.md)
- [검증](validation.md)
- [리팩토링](refactoring.md)

---

## 2. 작업 유형별 시퀀스

요청에서 작업 유형을 **먼저** 판단한다. 불명확하면 사용자에게 질문한다.  
**한 번에 하나씩** 순차 진행하고, 이전 단계 출력 없이 다음으로 넘어가지 않는다.

### 신규 개발
아무것도 없는 환경에서 새로 만드는 요청  
요구사항 → 설계 → 구현 → 검증

### 기능 추가
기존 코드에 새 요구사항 붙이기  
요구사항 → 탐색 → 설계 → 구현 → 검증

### 버그 수정
잘못된 동작을 바로잡기  
요구사항(재현 조건) → 탐색 → 구현(수정) → 검증(회귀)

### 리팩토링
동작 유지, 내부 구조 개선  
탐색 → 리팩토링 → 검증

### 최적화
동작 유지, 성능·메모리·비용 개선  
탐색(측정) → 리팩토링(병목) → 검증(재측정)

### 기능 제거
피처 삭제, deprecated 정리  
탐색(영향 범위) → 구현(제거) → 검증(회귀)

### 테스트 작성
기존 코드에 테스트 추가  
탐색 → 검증(작성)

### 보안 패치
취약점 수정  
요구사항(재현) → 탐색 → 구현(수정) → 검증(회귀)

### 의존성 업데이트
라이브러리 업그레이드 후 호환성 수정  
탐색(호환성) → 구현(수정) → 검증

### 통합
외부 API·서비스 연결  
요구사항 → 탐색 → 설계 → 구현 → 검증

### 포팅
다른 언어·플랫폼으로 이식  
탐색 → 설계 → 구현 → 검증

### 마이그레이션
기술 스택·플랫폼 교체  
요구사항 → 탐색 → 설계 → 구현 → 검증
