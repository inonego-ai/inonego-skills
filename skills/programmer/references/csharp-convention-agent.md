# C# 컨벤션 전담 에이전트

C# 구현 뒤의 컨벤션 검토와 컨벤션 범위 수정은 하나의 전담 작업으로 취급한다. 이 절차는 기능·설계 검토를 대신하지 않으며 C# 컨벤션 책임만 분리한다.

## 실행 조건과 모델

- 현재 호스트가 외부 프로세스나 별도 서비스가 아닌 자체 서브에이전트 실행 기능을 제공하고, 호출자가 서브에이전트 모델을 명시적으로 선택할 수 있을 때만 전담 에이전트를 사용한다.
- OpenAI 계열 런타임에서는 `GPT-5.6 Luna` 또는 호스트가 노출한 동등한 Luna 계열 모델을 사용한다.
- Claude 계열 런타임에서는 `Claude Haiku` 또는 호스트가 노출한 동등한 Haiku 계열 모델을 사용한다.
- 해당 모델 계열을 선택할 수 없으면 다른 고성능 모델을 임의로 대신 띄우지 않고 현재 에이전트가 직접 컨벤션 처리를 수행한다.
- 이 규칙만을 이유로 Orca, 별도 CLI 에이전트, MCP 외부 에이전트, 웹 서비스나 별도 프로세스를 실행하지 않는다.

## 위임 시점과 입력

- C# 구현 변경이 끝난 뒤, 최종 빌드·테스트처럼 파일의 최종 내용에 의존하는 검증보다 먼저 실행한다.
- 같은 파일을 수정하는 다른 에이전트나 작업과 동시에 실행하지 않는다.
- 전담 에이전트에는 이번 작업에서 쓰기가 발생한 C# 파일, 사용자 요청 범위, 적용되는 프로젝트 로컬 지침, 이 스킬의 C# 규칙과 검사 도구 문서를 제공한다.
- 기본 대상은 이번 작업에서 변경한 C# 파일이다. 규칙이 파일 전체의 동일 패턴에 적용되면 해당 파일 안에서는 누락 없이 일관되게 적용한다.
- 프로젝트 전체나 관련 없는 C# 파일을 컨벤션 정리 대상으로 자동 확장하지 않는다.

## 전담 책임

- 전담 에이전트가 대상 파일의 C# 컨벤션 검토, 필요한 컨벤션 수정, 자동 검사 도구 실행과 재검사를 모두 맡는다.
- 적용 규칙의 기준은 [C# 코드 스타일 규칙](../conventions/csharp.md)이며, 더 구체적인 프로젝트 로컬 규칙이 대응 규칙을 재정의하면 프로젝트 규칙을 우선한다.
- 구조·컨벤션 자동 검사가 유효하면 [C# 구조·컨벤션 검사 도구](csharp-tool.md)를 직접 사용한다. 도구가 진단하지 않는 의미적 규칙도 전담 에이전트가 직접 확인한다.
- 수정 권한은 원래 사용자 요청이 허용한 범위를 그대로 상속한다. 읽기 전용 요청에서 새 수정 권한을 만들지 않는다.

- 컨벤션 수정은 서식, 문서화, region·멤버 배치, 규칙에 따른 제한된 식별자 표기처럼 동작 계약을 바꾸지 않는 범위에 한정한다.
- 공개 API, 직렬화 계약, 외부 연동 이름, 기능 동작, 책임 구조나 아키텍처를 컨벤션만을 이유로 변경하지 않는다. 그런 변경이 필요해 보이면 미해결 항목으로 남긴다.
- 같은 진단이나 수정 시도가 반복 실패하면 우회 코드를 늘리지 말고 원인과 미해결 상태를 보고한다.

## 완료와 호출자 책임

- 전담 에이전트는 적용한 파일, 수행한 컨벤션 수정, 자동 검사 결과와 남은 미해결 항목을 반환한다.
- 모든 대상 파일의 컨벤션 처리가 완료됐거나, 컨벤션 범위를 넘어서는 이유로 남겨야 할 항목이 명확히 구분되면 종료한다.
- 전담 에이전트가 정상 완료한 경우 호출자는 같은 파일을 C# 컨벤션 관점으로 다시 수동 검토하거나 같은 검사 도구를 재실행하지 않는다. 이후의 기능 검증, 컴파일, 테스트와 런타임 확인은 별도 책임이다.
- 서브에이전트 실행 자체가 불가능하거나 모델 선택 실패, 도구 오류, 중단 또는 불완전 결과로 전담 처리가 완료되지 못하면 호출자가 남은 컨벤션 처리를 직접 이어받는다.
- 전담 에이전트가 일부 파일을 수정한 뒤 실패했다면 호출자는 그 변경을 보존한 상태에서 대상 파일 전체의 컨벤션 완료 상태를 직접 마무리한다.
