# C# 컨벤션 전담 에이전트

C# 구현 뒤의 컨벤션 검토와 컨벤션 범위 수정을 하나의 전담 작업으로 취급한다. 기능·설계 검토를 대신하지 않고 C# 컨벤션 책임만 분리한다.

## 실행 조건과 모델

- 호스트가 외부 프로세스·별도 서비스가 아닌 자체 서브에이전트 실행을 제공하고 호출자가 모델을 명시적으로 고를 수 있을 때만 사용한다.
- OpenAI 계열 런타임은 `GPT-5.6 Luna` 또는 호스트가 노출한 동등한 Luna 계열을, Claude 계열 런타임은 `Claude Haiku` 또는 동등한 Haiku 계열을 쓴다.
- 해당 계열을 고를 수 없으면 다른 고성능 모델을 대신 띄우지 않고 현재 에이전트가 직접 처리한다. 이 규칙만으로 Orca, 별도 CLI 에이전트, MCP 외부 에이전트, 웹 서비스, 별도 프로세스를 실행하지 않는다.

## 위임 시점과 입력

- C# 구현 변경이 끝난 뒤, 최종 빌드·테스트처럼 파일 최종 내용에 의존하는 검증보다 먼저 실행하며, 같은 파일을 수정하는 다른 작업과 동시에 실행하지 않는다.
- 전담 에이전트에는 이번 작업에서 쓰기가 발생한 C# 파일, 사용자 요청 범위, 프로젝트 로컬 지침, 이 스킬의 C# 규칙과 검사 도구 문서를 제공한다.
- 기본 대상은 이번에 변경한 C# 파일이다. 규칙이 파일 전체의 동일 패턴에 적용되면 그 파일 안에서는 누락 없이 적용하되, 프로젝트 전체나 무관한 C# 파일로 자동 확장하지 않는다.

## 전담 책임

- 대상 파일의 컨벤션 검토, 필요한 수정, 자동 검사 도구 실행과 재검사를 모두 맡는다.
- 기준은 [C# 코드 스타일 규칙](../conventions/csharp.md)이며 더 구체적인 프로젝트 로컬 규칙이 대응 규칙을 재정의하면 프로젝트 규칙을 우선한다.
- 자동 검사가 유효하면 [C# 구조·컨벤션 검사 도구](csharp-tool.md)를 직접 쓰고, 도구가 진단하지 않는 의미적 규칙도 직접 확인한다.
- 수정 권한은 원래 사용자 요청이 허용한 범위를 상속하며 읽기 전용 요청에서 새 수정 권한을 만들지 않는다.
- 수정은 서식, 문서화, region·멤버 배치, 규칙에 따른 제한된 식별자 표기처럼 동작 계약을 바꾸지 않는 범위로 한정한다. 공개 API, 직렬화 계약, 외부 연동 이름, 기능 동작, 책임 구조를 컨벤션만을 이유로 바꾸지 않고 필요해 보이면 미해결 항목으로 남긴다.
- 같은 진단이나 수정이 반복 실패하면 우회 코드를 늘리지 말고 원인과 미해결 상태를 보고한다.

## 완료와 호출자 책임

- 적용한 파일, 수행한 수정, 자동 검사 결과, 남은 미해결 항목을 반환한다. 모든 대상 파일의 처리가 끝났거나 컨벤션 범위를 넘는 항목이 명확히 구분되면 종료한다.
- 정상 완료 시 호출자는 같은 파일을 C# 컨벤션 관점으로 다시 검토하거나 같은 검사 도구를 재실행하지 않는다. 이후 기능 검증, 컴파일, 테스트, 런타임 확인은 별도 책임이다.
- 서브에이전트 실행 불가, 모델 선택 실패, 도구 오류, 중단, 불완전 결과로 완료되지 못하면 호출자가 남은 처리를 이어받는다. 일부 파일 수정 뒤 실패했다면 그 변경을 보존한 채 대상 파일 전체의 컨벤션 완료 상태를 마무리한다.
