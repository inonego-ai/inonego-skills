# 범용 코드 작업

## 적용

- 코드 파일을 읽거나 쓰기 시작할 때 적용한다.
- 코드 쓰기에는 현재 언어의 코딩 규칙 문서를 적용한다. 문서를 쓸 수 없으면 임의 스타일로 대체하지 않고 적용 불가 범위를 밝힌다. 규칙 문서가 없는 언어는 프로젝트의 기존 스타일과 로컬 규칙을 따른다.
- 코딩 규칙이 같은 구조 전체에 적용되면 수정 지점만 맞추지 말고 같은 범위의 동일 패턴 누락도 확인한다.
- 코드 식별자·파일·폴더 이름을 제안·변경·검토할 때는 [명명 취향](references/naming-preferences.md)을 적용한다.

## 구현·명명 판단

- 증상 위치보다 책임 주체, 호출 흐름, 데이터 생성·소비 경계를 먼저 확인한다.
- 기존 책임 주체와 자연스러운 확장 지점을 우선한다. 도달 가능한 요구 없이 추상화·복구 상태·방어 분기를 추가하지 않는다.
- 컬렉션 소유권 종료와 일괄 정리 문제가 실제로 나오면 [소유 컬렉션 일괄 정리](references/owned-collection-cleanup.md)를 적용한다.
- 이름은 도메인, 책임, 수명, 소유권과 기존 프로젝트 용어를 확인한 뒤 정한다. 승인된 이름 변경은 철자가 비슷한 심볼이 아니라 의미와 책임이 같은 참조 범위에 일관되게 적용한다.

## 변경 검토

- 여러 심볼 오류가 연쇄되면 개별 증상보다 네임스페이스 가림, 공통 참조, 생성 코드, 어셈블리 경계 같은 공통 원인을 먼저 본다.
- 수정 뒤 변경 차이에서 요청 밖 변경, 같은 구조의 적용 누락, 이름·참조 범위를 검토한다. 컨벤션 전담 절차가 있는 언어는 그 절차의 규칙 검토를 호출자가 중복하지 않는다.
- 같은 문제에 수정이 두 번 이상 실패했거나 방어 분기가 늘면 다음 수정 전에 가정, 실행 경로, 책임 경계를 다시 검토한다.

## 언어별 규칙

쓰기 작업에만 적용한다.

- C# / Unity: [C# / Unity 규칙](conventions/csharp.md). 구현 뒤 컨벤션 검토·수정은 [C# 컨벤션 전담 에이전트](references/csharp-convention-agent.md)에 따른다.
  - 런타임이 서브에이전트 실행과 모델 선택을 지원하면 변경한 C# 파일의 컨벤션 처리를 전담 에이전트에 위임하고, 정상 완료하면 호출자는 같은 검토나 검사 도구 실행을 반복하지 않는다.
  - 서브에이전트나 지정 모델을 쓸 수 없거나 전담 처리가 실패하면 현재 에이전트가 같은 범위를 직접 처리한다.
  - 자동 검사가 필요하면 실제 담당 주체가 [C# 구조·컨벤션 검사 도구](references/csharp-tool.md)를 쓴다. 일반 코드 작업에는 도구 세부 명령을 미리 읽지 않는다.
