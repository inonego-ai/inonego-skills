# 범용 코드 규칙

**단일 책임 최우선**  
설계·구현의 모든 단위(함수·클래스·모듈)는 단일 책임을 갖도록 분리한다.  
로직·표현이 한 단위에 섞이지 않게 한다.

구현이 비대해지는 경우 아래 순서로 정리한다:
1. 단일 책임 원칙 — 하나의 단위가 하나의 역할만 갖도록 경계 재구성
2. 응집도 최대화 — 같은 이유로 변경되는 것끼리 모음
3. 결합도 최소화 — 다른 이유로 변경되는 것끼리 분리
4. 클래스 또는 메서드 추출 — 위 원칙에 따라 필요한 단위를 추출

**의도 파악**  
코드와 주석에서 현재 요청사항과 다른 부분이 있으면 구현 전에 질문한다.

**가독성 중요**  
논리 단위 사이에 빈 줄을 넣어 시각적으로 구분하고, 의미가 달라지는 지점마다 주석이나 구분선으로 맥락을 전달.

## 기본 컨벤션 규칙

**컨벤션 규칙 문서 로드**
쓰기 작업 시에만 현재 언어에 맞춰 로드한다. 없는 경우 패스한다.
- [C# / Unity](conventions/csharp.md)

**컨벤션 규칙은 모든 동일한 패턴에 예외 없이 적용한다.**  
명시적으로 다룬 예시뿐 아니라 구조가 같은 모든 경우에 동일하게 적용해야 한다.  
규칙을 적용할 때는 "이 패턴과 구조가 같은 다른 곳은 없는가"를 항상 확인한다.

## 주석 규칙

**[주석] 순서 번호 금지.** `// 1.` 스타일 금지 — 순서가 존재하더라도 번호 대신 의미 있는 이름으로.  
**[주석] 변경 이력 금지.** 주석은 항상 현재 상태를 기준으로 작성한다. `(변경 내용)`을 추가하지 않는다.

**[주석] 핵심 로직에는 의도(WHY)·작동 방식(HOW)을 필요한 만큼 작성한다.**  
목표는 나중에 봐도 그 의도를 이해하고 유지하도록 하는 것이다.  
그 외에는 장황하지 않게 적당한 수준으로 작성한다.  
자명한 내용은 굳이 주석으로 설명하지 않아도 된다.

## 블럭 헤더 규칙

``` csharp
/* BLOCK_HEADER_BEGIN =======================================================================
파일명 : FileName.cs
수정일 : YYYY-MM-DD

# 설명
이 파일이 하는 일을 대략적으로 설명한다.
 
# 특이사항, 제약사항 (필요에 따라 항목 추가 가능)
특이사항, 제약사항이나 향후 계획 등등을 작성한다.
========================================================================= BLOCK_HEADER_END */
```

### 쓰기 규칙

- 쓰기 내용은 기본적으로 양식을 따르되, 필요에 따라 주석 틀을 해치지 않는 선에서 마크다운 형식으로 자유롭게 작성한다.

- 파일에 **쓰기 작업**이 발생하는 경우:
  - 블럭 헤더가 없으면 → 반드시 작성
  - 블럭 헤더가 있고 내용이 달라졌으면 → 수정 (수정일 포함)
- **읽기 전용** 작업이면 → 블럭 헤더 추가·수정 불필요
