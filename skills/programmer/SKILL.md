# 범용 코드 규칙

## 적용 절차

- 코드 파일을 읽거나 쓰는 작업을 시작할 때 이 스킬을 실제로 읽는다.
- 코드 쓰기 작업은 첫 수정 전에 대상 언어 컨벤션을 읽는다. 대화가 압축되면 현재 코드 작업을 계속하기 전에 이 스킬과 언어 컨벤션을 다시 읽는다.
- 컨벤션을 읽지 못했으면 임의 스타일로 수정하지 않고 누락된 문서와 적용할 수 없는 범위를 밝힌다.
- 스킬을 읽었다는 선언으로 대신하지 않고 변경한 모든 코드 파일과 구조가 같은 범위에 실제 규칙을 적용한다.

## 테스트 작업 경계

- 코드 작업 중 새 테스트나 테스트 전용 구성이 필요해 보여도 사용자가 만들거나 추가하라고 명시했는지 먼저 확인한다.
- 명시적 요청이 없으면 테스트를 추가하지 않고 검증할 계약, 필요한 이유, 테스트 후보만 제안한다.
- 테스트 실행은 생성 권한과 별개이므로 요청 또는 합의된 검증 범위에 포함됐는지 확인한다.
- 테스트 작업이 허용된 경우에만 `test-design`을 적용해 기대 결과의 근거와 검증 경계를 정한다.

## 기본 컨벤션 규칙

**컨벤션 규칙 문서 로드**
쓰기 작업 시에만 현재 언어에 맞춰 로드한다. 없는 경우 패스한다.
- [C# / Unity](conventions/csharp.md)

**컨벤션 규칙은 모든 동일한 패턴에 예외 없이 적용한다.**  
명시적으로 다룬 예시뿐 아니라 구조가 같은 모든 경우에 동일하게 적용해야 한다.  
규칙을 적용할 때는 "이 패턴과 구조가 같은 다른 곳은 없는가"를 항상 확인한다.

## 컬렉션 일괄 정리 규칙

개별 `Remove`·`Release`·`Dispose`가 항목 정리와 소유 컬렉션 제거를 함께 수행하고, `All` 메서드가 같은 컬렉션 전체를 정리한다면 다음 구조를 우선한다.

- 공통 내부 메서드에 컬렉션 제거 여부를 나타내는 `bool`을 두고 기본값을 `true`로 한다. 이름은 일반명보다 `removeFromAcquired`처럼 실제 소유 컬렉션이 드러나게 짓는다.
- 개별 처리는 기본값으로 호출하고, `All`에서는 제거 여부를 `false`로 전달해 원 컬렉션을 직접 순회한 뒤 마지막에 한 번 `Clear()`한다.
- 모든 항목의 정리를 끝까지 시도해야 한다면 반복문 안에서 항목별 예외를 수집하고, 순회를 마친 뒤 컬렉션 정리와 오류 전달을 수행한다.
- 순회 중 변경을 피하려는 목적만으로 스냅샷이나 임시 컬렉션을 만들지 않는다.

이 패턴은 개별 처리의 직접·간접 호출이 순회 중인 컬렉션을 변경하지 않고, 각 항목의 정리 시도가 끝나면 성공 여부와 관계없이 논리적 소유권이 종료되는 계약일 때 적용한다. 실패한 항목을 계속 소유해야 한다면 마지막에 일괄 `Clear()`하지 않는다. 가능성만 추측해 방어 구조를 추가하지 말고 실제 호출 흐름과 소유권 계약을 확인한다.

## 명명 판단

- 특정 영단어를 일률적으로 금지하지 않는다.
- 이름을 정하기 전에 대상의 도메인, 책임, 수명, 소유권, 기존 프로젝트 용어를 확인한다.
- 접두사·핵심 명사·접미사가 각각 실제 의미를 나타내는지 비교한다.
- 사용자의 질문이나 이름 후보는 변경 승인으로 취급하지 않는다. 의미와 적용 범위를 설명하고 승인을 받은 뒤 변경한다.
- 승인된 변경은 철자가 비슷한 모든 심볼로 넓히지 않고 의미와 책임이 같은 심볼, 파일, 직렬화·설정 이름, 호출 참조 범위를 확인해 일관되게 적용한다.

## 컴파일 오류와 변경 검토

- 한 변경 뒤 여러 심볼 오류가 연쇄적으로 발생하면 개별 `using`이나 타입을 차례로 패치하기 전에 네임스페이스 가림, 공통 참조, 생성 코드, 어셈블리 경계 같은 공통 원인을 확인한다.
- 수정 뒤 변경 차이에서 요청 밖 변경, 컨벤션 누락, 같은 구조의 적용 누락, 이름·참조 범위를 검토한다.
- 변경 차이 명령을 실행했다는 사실만으로 검토가 끝났다고 판단하지 않는다.
