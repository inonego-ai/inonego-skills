# 범용 코드 작업

코드 작업의 공통 판단 기준이다.

## 적용 절차

- 코드 파일을 읽거나 쓰기 시작할 때 이 스킬을 적용한다.
- 코드 쓰기에는 현재 언어에 대응하는 코딩 규칙 문서가 있으면 적용한다. 해당 규칙 문서를 사용할 수 없으면 임의 스타일로 대체하지 않고 적용할 수 없는 범위를 밝힌다. 별도 규칙 문서가 없는 언어는 기존 프로젝트 스타일과 확인된 로컬 규칙을 따른다.
- 코딩 규칙이 동일한 구조 전체에 적용되는 경우, 해당 규칙의 실제 처리 주체는 수정 지점만 맞추지 말고 같은 범위의 동일 패턴 누락도 확인한다.
- 코드 식별자·파일·폴더 이름을 제안하거나 변경·검토할 때는 [명명 취향](references/naming-preferences.md)을 적용한다.
- 구조 문제는 실제 책임과 호출 흐름으로 판단한다. 별도 정렬 모드는 사용자가 명시적으로 호출한 경우에만 적용한다.

## 구현 판단

- 증상 위치보다 실제 책임 주체, 호출 흐름과 데이터 생성·소비 경계를 먼저 확인한다.
- 기존 책임 주체와 자연스러운 확장 지점을 우선하고, 도달 가능한 요구 없이 새 추상화·복구 상태·방어 분기를 추가하지 않는다.
- 특정 구현 수단보다 현재 계약과 소유권을 만족하는 가장 단순한 구조를 선택한다.
- 컬렉션 소유권 종료와 일괄 정리 문제가 실제로 등장하면 [소유 컬렉션 일괄 정리](references/owned-collection-cleanup.md)를 적용한다.

## 명명 판단

- 이름을 정하기 전에 대상의 도메인, 책임, 수명, 소유권과 기존 프로젝트 용어를 확인한다.
- 승인된 변경은 철자가 비슷한 모든 심볼로 넓히지 않고 의미와 책임이 같은 참조 범위에 일관되게 적용한다.

## 변경 검토

- 한 변경 뒤 여러 심볼 오류가 연쇄적으로 생기면 개별 증상보다 네임스페이스 가림, 공통 참조, 생성 코드와 어셈블리 경계 같은 공통 원인을 먼저 확인한다.
- 수정 뒤 변경 차이에서 요청 밖 변경, 같은 구조의 적용 누락과 이름·참조 범위를 검토한다. 별도 컨벤션 전담 절차가 정의된 언어는 그 절차가 맡은 규칙 검토를 호출자가 중복하지 않는다.
- 같은 문제에 두 번 이상 수정이 실패했거나 방어 분기가 늘어나면 다음 수정 전에 가정·실행 경로·책임 경계를 다시 검토한다.

## C# 컨벤션 처리

C# 쓰기 작업은 [C# / Unity 규칙](conventions/csharp.md)을 적용하고, 구현이 끝난 뒤의 컨벤션 검토·수정 단계는 [C# 컨벤션 전담 에이전트](references/csharp-convention-agent.md)에 따라 처리한다.

- 현재 런타임이 자체 서브에이전트 실행과 모델 선택을 지원하면 변경한 C# 파일의 컨벤션 처리를 전담 에이전트에 위임한다. 전담 에이전트가 정상 완료하면 호출자는 같은 C# 컨벤션 검토나 검사 도구 실행을 반복하지 않는다.
- 자체 서브에이전트를 사용할 수 없거나 지정된 경량 모델을 선택할 수 없거나 전담 처리가 실패하면 현재 에이전트가 동일한 범위를 직접 처리한다.
- 구조·컨벤션 자동 검사가 필요할 때 실제 담당 주체는 [C# 구조·컨벤션 검사 도구](references/csharp-tool.md)를 사용한다. 일반 코드 작업에는 이 도구의 세부 명령과 종료 코드를 미리 로드하지 않는다.
