# 실패 경계와 정리

오류 처리, 실패 후 정리, 복구, 재시도나 여러 후속 처리가 구조 판단의 핵심일 때 적용한다.

## 검증 경계

- 현실적으로 발생 가능한 계약 위반은 상태 변경 전에 그 책임의 경계에서 검증한다.
- 통제 밖에서 상태가 바뀔 수 있는 경계를 지난 뒤에는 그 경계가 바꿀 수 있는 조건만 다시 검증한다.
- 정상 내부 흐름에서 발생할 수 없는 상태를 가정해 전용 분기·오류·복구 상태를 추가하지 않는다.
- 불변식이 깨질 수 있다는 근거가 있으면 방어 코드를 먼저 붙이지 말고 실제로 그 불변식을 깨는 경로와 책임 주체를 찾는다.
- 여러 독립 계약이 동시에 깨져야만 생기는 상황은 실제 요구나 재현 근거 없이 선제 대응하지 않는다.

## 실패 정리

- 실패 정리는 현재 작업이 직접 만들었고 아직 책임지는 미완료 상태와 자원만 다룬다.
- 이미 완료되어 되돌릴 수 없는 변경이나 다른 책임 영역의 상태까지 추측해 원상복구하지 않는다.
- 정리 후에도 최초 오류를 호출자가 관찰할 수 있게 한다.
- 정리 자체도 실패하면 최초 오류와 정리 오류를 모두 보존하고, 로그만 남긴 채 성공으로 반환하지 않는다.
- 여러 후속 처리를 끝까지 실행해야 일관성을 보존할 수 있으면 각 실패를 수집하고 필수 처리를 마친 뒤 함께 전달한다.
- 실패한 자원이나 소유권을 계속 유지해야 하는 계약이면 책임 주체가 그 미완료 상태를 계속 관리한다.

## 복구와 재시도

자동 복구·재시도는 다음 계약이 실제로 정의된 경우에만 추가한다.

- 재시도 단위가 무엇인지
- 중복 실행이 어떤 의미를 갖는지
- 언제 성공·종료·포기하는지
- 최종 실패를 호출자에게 어떻게 전달하는지

`일단 재시도`, `혹시 복구 가능` 같은 가능성만으로 숨은 반복 실행이나 새 상태 모델을 만들지 않는다.
