# 셰이더 원본 이식

기존 셰이더나 절차적 렌더링 구현을 Unity로 옮길 때 적용한다. 목표는 비슷한 효과를 새로 설계하는 것이 아니라 원본 렌더링 알고리즘을 Unity 실행 환경으로 번역하는 것이다.

## 기준 원본

- 결과 이미지보다 실제 소스와 입력 설정을 우선한다. 셰이더 본문뿐 아니라 포함 파일, 보조 함수, 정점 처리, 여러 패스, 중간 버퍼, 텍스처 생성, 매개변수 전달 코드까지 확인한다.
- 원본의 좌표계, 입력값, 시간, 텍스처, 렌더 상태, 합성 순서를 하나의 구현 계약으로 본다. 확인되지 않은 의도나 더 나은 효과를 추측해 넣지 않는다.
- 원본 전체를 확보하지 못했으면 보이는 결과만으로 동일 구현을 복원했다고 주장하지 않고 확인한 부분과 누락된 입력·단계를 먼저 구분한다.

## 보존할 내용

Unity 쪽 문법과 연결 구조가 달라져도 다음 의미와 처리 순서는 유지한다. 하나라도 바꾸면 비슷해 보여도 같은 구현이 아니다.

- 좌표 기준, 정규화, 원점, 축 방향, 종횡비 보정, 정점 변형, UV 생성·변환 순서
- 수식, 상수, 임계값, 반복 횟수, 함수 호출 순서, 해시·난수·노이즈·거리 함수·마스크의 원래 알고리즘
- 시간 단위, 속도, 위상, 반복 주기, 프레임 의존성
- 텍스처 채널, 샘플링 좌표, 필터, 래핑, 밉맵, 정밀도
- 색 계산 순서, 색 공간, 감마, 톤 변환, 알파 표현
- Blend, Cull, ZTest, ZWrite, Stencil, Clip, 렌더 순서와 여러 패스·중간 렌더 대상 사이의 입력·출력·합성 순서
- 노출 매개변수의 의미, 기본값, 범위, 상호 관계

## Unity에 맞게 변환할 부분

원본 의미를 유지하기 위한 실행 환경 변환으로만 다룬다.

- 셰이딩 언어의 문법·자료형·내장 함수를 HLSL과 대상 렌더 파이프라인 형식으로 변환하고, Uniform·상수 버퍼·텍스처·Sampler를 머티리얼 속성과 바인딩으로 연결한다.
- 화면 좌표, UV 방향, 깊이 범위 차이는 명시적 변환으로 흡수한다.
- 원본 렌더 상태와 합성 순서를 Pass, Render Queue, Stencil, 렌더 텍스처, 호출 구조로 대응한다.
- 엔진의 시간·화면 크기 값은 그대로 대입하지 말고 원본 단위와 의미에 맞춰 변환한다.
- 대상 프로젝트의 렌더 파이프라인과 기존 셰이더 구조를 따르되 원본 계산 결과를 바꾸지 않는다.

Unity 구조가 다르다는 이유로 원본 패스나 계산 단계를 생략하지 않는다. 단계를 합치거나 나눠야 하면 중간값과 최종 합성 결과가 같은지 확인한다.

## 재해석 방지

- 익숙하거나 쉽다는 이유로 다른 노이즈·그라데이션·마스크·왜곡 알고리즘으로 교체하지 않으며, 결과를 텍스처나 정적 이미지로 굳혀 절차적 동작을 대신하지 않는다.
- 원본 상수와 색을 눈대중으로 조정하기 전에 좌표계, 색 공간, 샘플링, 렌더 상태 차이부터 해결한다.
- 성능 최적화, 단계 축소, 코드 정리는 원본과 일치하는 결과를 확보한 뒤에 한다.
- 원본에 없는 무작위성, 색 변화, 보간, 움직임, 예외 처리를 추가하지 않으며 차이의 원인을 확인하지 않은 채 엔진 특성이나 부동소수점 오차로 단정하지 않는다.
- 정확한 대응이 불가능한 기능이 있으면 임의 효과로 대체하기 전에 재현할 수 없는 입력·연산, 결과 차이, 필요한 대안을 밝힌다.

## 비교와 검증

1. 원본과 Unity에 같은 해상도, 종횡비, 텍스처, 매개변수, 시간, 난수 입력을 쓴다.
2. 정지 화면은 같은 시점의 결과를 겹치거나 차이 영상으로 비교하고, 움직이는 효과는 여러 시점에서 시작 시점·주기·속도·위상을 비교한다.
3. 차이는 좌표계 → 색 공간 → 알파·합성 → 샘플링 → 시간 → 매개변수 전달 → 패스 순서 순으로 원인을 좁히고, 원본 수식을 바꿔 덮기 전에 플랫폼 변환이 맞는지 다시 확인한다.

컴파일 성공이나 정적 비교만으로 시각적 동일성을 주장하지 않는다. 실제 Unity 렌더링을 원본과 비교하지 못했다면 이식된 범위와 시각적으로 검증하지 못한 범위를 나눠 보고한다.
