# Unity 개발

Unity 고유 실행 환경과 자산 연결을 다룰 때 사용한다. 코드 작업에는 `programmer`를 함께 적용한다.

## 대상과 증거 확인

- 프로젝트, 작업 사본, 패키지, 씬, 프리팹, 자산과 데이터의 정확한 이름과 실제 경로를 확인한다.
- 코드·데이터·씬·프리팹·문서의 상태를 서로 다른 근거로 취급한다.
- 자산이나 데이터의 실제 소유자·실행 주체와 런타임 소비 경로를 추적한다.
- 정적 확인, 컴파일, Test Runner, 에디터 새로 고침, 플레이 모드, 시각 확인과 직접 실행을 구분해 보고한다.
- 씬이나 프리팹 저장 뒤에는 자동 직렬화로 요청 밖 변경이 섞였는지 확인하고 기존 사용자 변경을 보존한다.
- UI 작업은 실제 렌더링 경계와 입력 소유권을 확인하고 상태 전환의 양방향과 입력 위치가 바뀌지 않은 경우도 검토한다.
- 일반 소스·자산 조사에서는 특별한 근거가 없는 한 `Library`, `Temp`, `obj`, `Logs`, `Build`, `Builds`, `.git` 같은 생성물·캐시 영역을 제외한다.

## 특수 작업 절차

- 기존 셰이더나 절차적 렌더링 구현을 Unity로 옮길 때는 [셰이더 원본 이식](references/shader-porting.md)을 적용한다.
- Unity 테스트 변경이 승인된 경우에만 `test-design`과 [Unity 테스트 배치와 작성 규칙](references/testing.md)을 적용한다.
