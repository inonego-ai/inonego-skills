# 테스트 가능한 코드 만들기

설계 단계에서 테스트 가능성을 확보하는 방법.  
구현 후에 테스트를 억지로 끼워 넣는 것보다, 설계에서 미리 대비하는 쪽이 훨씬 싸다.

---

## 핵심 질문

설계 단위를 하나 정할 때마다 아래를 묻는다. 답하기 어렵다면 설계가 테스트 가능하지 않다.

- 이 단위를 테스트에서 어떻게 실행할 것인가
- 모든 의존성을 대체할 수 있는가
- 실제 I/O 없이 실행할 수 있는가
- 병렬로 실행해도 서로 간섭하지 않는가
- 결과를 직접 관찰할 수 있는가

---

## 테스트 가능성을 떨어뜨리는 패턴

| 패턴 | 증상 | 왜 문제인가 |
|------|------|------------|
| **직접 생성** | 함수 안에서 구체 클래스를 직접 생성 | 테스트에서 대체 불가 |
| **숨겨진 싱글턴** | 전역 인스턴스에 암묵적으로 의존 | 테스트 간 격리 불가 |
| **정적 I/O** | 시간·난수·파일·네트워크를 정적 메서드로 직접 호출 | 대체·고정 불가 |
| **전역 상태** | 모듈 레벨 변수·공유 상태 | 테스트 순서에 따라 결과가 달라짐 |
| **생성자의 부작용** | 생성 시점에 파일 읽기·네트워크 호출 수행 | 인스턴스를 만드는 것 자체에 I/O가 동반 |
| **거대한 단위** | 한 단위가 로직·I/O·표현을 모두 수행 | 테스트할 부분만 격리 불가 |

---

## 테스트 가능성을 확보하는 원칙

### 1. 의존성 주입
구체 의존성을 직접 생성하지 말고 외부에서 받는다. 생성자·함수 파라미터로 전달한다.

### 2. 경계 뒤로 I/O 격리
DB·파일·네트워크·시간·난수는 인터페이스 뒤에 둔다. 도메인 로직은 이 인터페이스에만 의존한다.

### 3. 순수 함수 선호
같은 입력이면 같은 출력을 내는 단위를 먼저 추출한다. 부작용이 있는 부분은 얇은 껍질로 분리한다.

### 4. 컨텍스트를 주입으로
"현재 시간", "현재 사용자" 같은 컨텍스트는 전역에서 꺼내지 말고 주입받는다.

### 5. 단일 책임으로 쪼개기
로직·데이터 변환·I/O가 한 단위에 섞여 있으면 테스트할 부분만 분리할 수 없다. 책임을 나눈다.

---

## 설계 단계 체크리스트

각 컴포넌트에 대해 확인한다.

- [ ] 필수 의존성을 대체 가능한 형태(인터페이스·주입)로 받는가
- [ ] 외부 I/O(DB·파일·네트워크·시간·난수)가 경계 뒤에 있는가
- [ ] 전역 상태·싱글턴에 의존하지 않는가
- [ ] 테스트용 대역으로 의존성을 대체할 수 있는가
- [ ] 로직만 담긴 순수 단위가 존재하는가
- [ ] 병렬 테스트에서 충돌할 공유 자원이 없는가

하나라도 "아니오"라면 해당 컴포넌트의 경계·의존성 방향을 재검토한다.

## 결정 가이드

**어디까지 격리해야 하는가?**  
도메인 로직(요구사항의 핵심)은 외부 I/O 없이 단위 테스트 가능해야 한다. 인프라 인접 코드(어댑터·리포지토리)는 통합 테스트로 검증하되, 그 안에 도메인 로직을 섞지 않는다.

**모든 것을 주입해야 하는가?**  
값 객체·순수 계산 유틸처럼 I/O도 상태도 없는 단위는 주입할 필요가 없다. 주입은 **대체 가능성이 필요할 때**만 적용한다. 필요 없는 곳까지 주입을 강요하면 설계가 부풀어진다.

**테스트가 불가능하면 어떻게 하나?**  
구현을 바꾸기 전에 설계를 먼저 고친다. 테스트 불가능은 설계 문제의 증상이다.

---

## 관련 주제

테스트 가능 설계는 아래 주제와 연결된다. 이 문서는 **설계 관점**에 집중하고, 아래는 필요할 때 별도로 다룬다.

- **테스트 대역** — dummy / stub / fake / spy / mock. 의존성을 실제 대신 대체하는 객체들.  
"무엇을 격리할지"는 설계가 정하고, "어떻게 대체할지"는 대역이 정한다.
- **표현 계층 패턴** — MVC / MVP / MVVM 등. UI 앱에서 각 층을 독립 테스트하려면 층 분리가 전제다.  
로직은 뷰 바깥에 있어야 뷰 없이 테스트할 수 있다.
- **Humble Object 패턴**
— 테스트가 어려운 경계층(UI·I/O)은 얇게 유지하고 로직은 테스트 가능한 층으로 옮기는 원칙.  
위의 표현 계층 패턴이 이 원칙의 구체적 적용 예.
