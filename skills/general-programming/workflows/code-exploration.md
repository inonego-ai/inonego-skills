# 코드 탐색

기능 추가·버그 수정·리팩토링 등 기존 코드가 있는 작업에서 구현 전에 수행하는 단계.  
기존 **패턴과 구조**를 파악해 구현 방향을 결정한다.

> 탐색 과정을 단일 에이전트에 통째로 위임하지 않는다.  
> 각 단계는 Claude가 직접 수행하고, 필요한 경우에만 에이전트를 활용한다.

---

## 단계 체크리스트

순서대로 수행한다.

- [ ] **0.** 작업 유형 결정
- [ ] **1.** 툴 준비 및 Serena 프로젝트 활성화
- [ ] **2.** 진입점 파악
- [ ] **3.** 유저 확인
- [ ] **4.** 코드 읽기
- [ ] **5.** 탐색 결과 요약

각 단계 시작 전에 위 체크리스트를 보고 이전 단계 출력이 있는지 확인한다.

---

## 0. 작업 유형 결정

**출력**: 작업 유형 (한 줄로 명시)

| 작업 유형 | 탐색 범위 | 진입점 규모 |
|---------|---------|---------|
| 버그 수정 | 재현 경로 + 연관 모듈 | 좁게 |
| 기능 추가 | 연관 모듈 + 패턴 파악 | 중간 |
| 리팩토링·구조 탐색 | 전체 구조·의존성 | 넓게 |

---

## 1. 툴 준비 및 Serena 프로젝트 활성화

**툴 스키마 일괄 로드** — 탐색에 쓸 툴셋을 **한 번의 ToolSearch**로 로드한다:

- **Serena 툴**
`activate_project`, `read_file`  
`search_for_pattern`, `get_symbols_overview`, `find_symbol`
- **TodoWrite 툴**

분할 로드는 스키마 중복 전송 낭비 — 금지.

**탐색 툴 규칙 읽기**  
Read 툴로 다음 경로를 읽는다.  
`${CLAUDE_PLUGIN_ROOT}/skills/general-programming/references/_exploration-tools.md`  
이미 읽은 경우 생략한다.

**Serena 프로젝트 활성화** — `activate_project`를 **직접** 호출한다 (에이전트 위임 금지).  
이미 활성화된 경우 "already active" 메시지가 반환되며 그대로 진행한다.  
이후 모든 하위 에이전트는 activate 없이 Serena 툴을 사용할 수 있다.

## 2. 진입점 파악
`inonego-skills:code-entry` 에이전트에 위임한다.  

---

## 3. 유저 확인

**입력**: 2단계의 시스템 계층 + 진입점 + 읽기 계획

시스템 계층, 진입점, 읽기 계획을 유저에게 보여준다.  
**MUST: `AskUserQuestion` 또는 `asqu` 툴을 반드시 사용해**  
어느 범위까지 읽을지 유저에게 확인하고, 응답을 반영해 탐색 파일 목록을 확정한다.  
필요에 따라 읽기 계획을 수정한다.

**출력**: 유저가 확정한 파일 목록 + 읽기 계획 (4단계의 필수 입력)

---

## 4. 코드 읽기

**입력**: 3단계의 파일 목록 + 읽기 계획

각 파일의 읽기 방식은 **탐색 툴** 사용 규칙을 따른다.

읽기 계획에 지정된 읽기 방식대로 실행한다.

- 파일 읽기 / 심볼 찾기 — 방식이 같은 파일끼리 묶어 **직접** 병렬 실행한다.
- 탐색 위임 — 탐색 위임으로 선택된 파일들을 **에이전트 호출로 묶어서 처리한다.**

본문을 읽지 않은 심볼의 동작을 요약에 기록하지 않는다.

---

## 5. 탐색 결과 요약

**입력**: 4단계에서 읽은 모든 파일의 심볼 맵과 본문

탐색 후 구현 전에 아래 구조로 정리한다.  
과잉 요약은 탐색 범위 조정 실패 신호 — 필요 최소한으로 쓴다.

### 5-1. 핵심 흐름

`A → B → C → ...` 형태로 시스템 전체 메인 플로우를 간단히 요약한다.

### 5-2. 관련 파일 (도메인별)

자세한 경로명을 출력하지 않는다. 파일명만 출력해도 무방하다.  

- **[그룹]**
  - `파일명:line` — 역할
    - `파일명:line` — 역할  (계층이 자연스러울 때만 중첩)

중첩은 관계가 자명할 때만 필요한 만큼 쓴다. 억지로 상하위로 나누지 않는다  
— 계층 관계가 모호하면 플랫하게 유지.

### 5-3. 기존 패턴

- **[그룹]**
  - **[패턴 이름]** — 규칙

### 5-4. 주의사항

- **[그룹]**
  - [상태·순서·사이드이펙트] — 구현 시 영향
