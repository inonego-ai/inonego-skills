# General Programming

프로그래밍 작업을 작업 유형에 따라 필요한 워크플로우만 순차 로드한다.

> 단순한 한두 줄 수정·정보 질의는 이 하네스 없이 직접 응답해도 무방하다.  
> 여러 단계가 필요한 프로그래밍 작업에서만 활성화한다.

---

## 1. 작업 유형 감지

요청에서 작업 유형을 **먼저** 판단한다. 불명확하면 사용자에게 질문한다.

| 작업 유형 | 판단 기준 |
|-----------|----------|
| 신규 개발 | 아무것도 없는 환경에서 새로 만드는 요청 |
| 기능 추가 | 기존 코드에 새 요구사항 붙이기 |
| 버그 수정 | 잘못된 동작을 바로잡기 |
| 리팩토링 | 동작 유지, 내부 구조 개선 |
| 최적화 | 동작 유지, 성능·메모리·비용 개선 |
| 기능 제거 | 피처 삭제, deprecated 정리 |
| 테스트 작성 | 기존 코드에 테스트 추가 |
| 보안 패치 | 취약점 수정 |
| 의존성 업데이트 | 라이브러리 업그레이드 후 호환성 수정 |
| 통합 | 외부 API·서비스 연결 |
| 포팅 | 다른 언어·플랫폼으로 이식 |
| 마이그레이션 | 기술 스택·플랫폼 교체 |

---

## 2. 워크플로우 시퀀스 매트릭스

작업 유형별로 아래 순서대로 워크플로우를 로드한다.  
**한 번에 하나씩** 진행하고, 이전 단계 출력 없이 다음으로 넘어가지 않는다.

| 작업 유형 | 시퀀스 |
|-----------|--------|
| 신규 개발 | 요구사항 → 설계 → 구현 → 검증 |
| 기능 추가 | 요구사항 → 탐색 → 설계 → 구현 → 검증 |
| 버그 수정 | 요구사항(재현 조건) → 탐색 → 구현(수정) → 검증(회귀) |
| 리팩토링 | 탐색 → 리팩토링 → 검증 |
| 최적화 | 탐색(측정) → 리팩토링(병목) → 검증(재측정) |
| 기능 제거 | 탐색(영향 범위) → 구현(제거) → 검증(회귀) |
| 테스트 작성 | 탐색 → 검증(작성) |
| 보안 패치 | 요구사항(재현) → 탐색 → 구현(수정) → 검증(회귀) |
| 의존성 업데이트 | 탐색(호환성) → 구현(수정) → 검증 |
| 통합 | 요구사항 → 탐색 → 설계 → 구현 → 검증 |
| 포팅 | 탐색 → 설계 → 구현 → 검증 |
| 마이그레이션 | 요구사항 → 탐색 → 설계 → 구현 → 검증 |

> 공통 구조: 기능 추가·통합·마이그레이션 등은 "탐색 + 영향 범위 분석"이 앞에 붙은 후 신규 개발과 동일한 흐름(설계 → 구현 → 검증)으로 진행된다.  
> 핵심 흐름은 하나이고, 케이스별로 **앞뒤에 무엇이 붙는가**의 차이다.

## 3. 워크플로우

각 워크플로우는 **해당 단계에 진입할 때** 로드한다. 미리 전부 로드하지 않는다.

- [요구사항 분석](workflows/requirements-analysis.md) — WHAT/WHY 파악, 모호성 해소, MoSCoW 분류
- [코드 탐색](workflows/code-exploration.md) — 진입점 → 읽기 계획 → 핵심 흐름·패턴 요약
- [설계](workflows/design.md) — 범위 → 아키텍처 → 상세 설계 → 검증 → 블루프린트
- [구현](workflows/implementation.md) — 인터페이스 먼저 → 블루프린트 번역 → 자가 검증
- [검증](workflows/validation.md) — 단위 → 통합 → 인수 → 회귀 테스트
- [리팩토링](workflows/refactoring.md) — 스멜 감지 → 점진적 변환 → 동작 보존 검증

---

## 4. 사용 원칙

- **작업 유형을 먼저 결정** — 불명확하면 사용자에게 질문 (임의 판단 금지)
- **한 워크플로우씩 순차 진행** — 이전 단계 출력이 다음 단계의 입력
- **하위 단계에서 상위 단계의 결론이 흔들리면** 즉시 상위로 돌아가 수정 후 재진행
