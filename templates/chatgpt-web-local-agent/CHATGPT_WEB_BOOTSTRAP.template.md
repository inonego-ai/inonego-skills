# ChatGPT Web 로컬 에이전트 부트스트랩

## 목적과 적용 범위

ChatGPT Web에서 연결된 로컬 컴퓨터의 파일, 저장소, 개발 도구, 빌드, 테스트, Unity 프로젝트나 기타 로컬 리소스를 실제로 다룰 때만 적용한다.
일반 대화와 웹 검색에는 적용하지 않는다.

## 초기화 순서

로컬 작업을 시작할 때 다음 순서로 준비한다.

1. 전역 에이전트 지침이 존재하면 읽는다.
2. 사용자가 지정한 경로나 작업 대상에서 프로젝트 루트를 판별한다.
3. 프로젝트 루트의 알려진 로컬 지침 위치를 확인하고 존재하는 것만 읽는다.
4. 호스트가 이미 제공한 스킬 메타데이터와 로컬 스킬 루트를 확인한다.
5. 추가 탐색이 필요하면 각 `SKILL.md`의 머리말 메타데이터만 읽어 `name`, `description`과 필요한 호출 메타데이터를 확보한다.
6. 현재 요청에 필요한 최소 스킬 조합을 선택하고 선택한 `SKILL.md`만 전체 읽는다.
7. 스킬이 특정 참조 문서나 규칙 문서를 요구할 때만 해당 파일을 추가로 읽는다.
8. 실제 파일, 저장소, 프로세스와 도구 상태를 확인한 뒤 작업한다.

## 로컬 도구 호출 전략

ChatGPT Web의 연결된 로컬 도구는 호출당 고정 지연이 클 수 있다. 의미, 검증 가능성과 안전성을 해치지 않는 범위에서 MCP 호출 수를 줄이고, 한 호출 안에서 자연스럽게 처리할 수 있는 작업은 배치한다.

- 단일 파일 또는 파일의 필요한 범위를 읽을 때는 `read_file`을 사용한다.
- 여러 독립 파일의 전체 내용을 함께 읽어야 할 때는 `read_multiple_files`를 우선한다. 파일이 크거나 예상 출력이 큰 경우 목적과 문맥에 맞게 여러 묶음으로 나눈다.
- 단순 파일 내용 확인을 위해 `start_process`에서 `Get-Content`, `cat`, `type` 같은 명령을 대신 사용하지 않는다.
- Git, 빌드, 테스트, CLI 실행, 시스템 조회, 필터링·집계처럼 실제 프로세스 실행이 필요한 작업에는 `start_process`를 사용한다.
- 서로 독립적인 여러 CLI·조회 작업은 여러 MCP `start_process` 호출로 잘게 나누기보다 가능한 경우 하나의 `start_process` 안에 배치한다.
- 배치된 작업이 서로 독립적이고 side effect나 공유 출력 충돌이 없으면 PowerShell 7의 `ForEach-Object -Parallel` 등으로 로컬 병렬 실행할 수 있다. 동시성은 작업 특성에 맞게 제한한다.
- 선행 결과에 의존하는 작업, 같은 파일·Git 작업 트리·빌드 출력·패키지 상태를 변경하는 작업처럼 충돌 가능성이 있는 작업은 병렬화하지 않는다.
- 여러 MCP 호출을 동시에 발행해도 실제 backend 병렬 실행이 보장된다고 가정하지 않는다. 안전하게 묶을 수 있다면 MCP 바깥의 동시 호출보다 단일 MCP 호출 내부의 로컬 배치·병렬화를 우선한다.
- persistent shell은 여러 단계에서 동일 프로세스 상태를 유지해야 할 때 사용한다. 단순히 shell 시작 비용을 줄이기 위해 `interact_with_process`를 잘게 반복하지 말고, 한 interaction에 자연스럽게 묶을 수 있는 명령은 배치한다.
- 배치가 과도한 출력, context 낭비, 실패 격리 저하 또는 디버깅 난이도 증가를 만들면 적절한 단위로 분리한다.
- 성능 최적화보다 작업의 정확성, 사용자 요청 범위, 안전한 side effect 경계를 우선한다.

## 전역 지침

다음 전역 지침 파일이 존재하면 읽는다.

- `<GLOBAL_AGENT_INSTRUCTIONS>`

전역 지침은 공통 계약이며 더 구체적인 프로젝트 로컬 지침이 대응 규칙을 재정의하면 프로젝트 규칙을 우선한다.

## 프로젝트 루트와 지침

사용자가 프로젝트 루트를 직접 지정했다면 그 경로를 우선한다.
파일이나 하위 디렉터리만 지정했다면 현재 작업 맥락과 다음 마커를 함께 사용해 상위에서 루트를 찾는다.

- `.git`
- `AGENTS.md`
- `package.json`
- `*.sln`, `*.slnx`, `*.csproj`
- Unity의 `Assets`, `Packages`, `ProjectSettings` 조합

프로젝트 루트에서는 다음 알려진 위치만 먼저 확인한다.

- `<project>\AGENTS.md`
- `<project>\.agents\AGENTS.md`
- `<project>\.codex\AGENTS.md`
- `<project>\CLAUDE.md`

프로젝트 전체를 재귀 검색해 임의의 지침 파일을 수집하지 않는다. 더 세부적인 지침 계층이 실제로 사용된다는 근거가 있을 때만 추가 탐색한다.

## 스킬 탐색

호스트가 현재 작업에 사용할 수 있는 스킬 메타데이터를 이미 제공했다면 그것을 우선 사용하고 동일한 로컬 복사본을 다시 전체 읽지 않는다.
추가 탐색이 필요하면 다음 전역 스킬 루트 중 존재하는 경로를 사용한다.

- `<GLOBAL_SKILL_ROOT_1>`
- `<GLOBAL_SKILL_ROOT_2>`
- `<GLOBAL_SKILL_ROOT_3>`

프로젝트에서는 다음 스킬 루트를 확인한다.

- `<project>\.agents\skills`
- `<project>\.codex\skills`
- `<project>\.claude\skills`

각 루트의 직계 하위 디렉터리에서 `SKILL.md` 머리말 메타데이터만 먼저 읽는다. `skills` 밖의 템플릿·문서·예제는 스킬 탐색 대상으로 취급하지 않는다.

같은 `name`의 로컬 스킬이 여러 출처에서 발견되면 한 개의 유효한 출처를 선택한다.

1. 프로젝트 로컬 스킬을 전역 스킬보다 우선한다.
2. 프로젝트 내부에서는 `.agents/skills` → `.codex/skills` → `.claude/skills` 순으로 선택한다.
3. 전역 내부에서는 위에 나열한 스킬 루트 순서를 따른다.
