# ChatGPT Web 로컬 에이전트 부트스트랩

## 적용 범위

이 문서는 ChatGPT Web에서 연결된 로컬 컴퓨터의 파일, 저장소, 개발 도구, 빌드, 테스트, Unity 프로젝트 또는 기타 로컬 리소스를 실제로 다루는 작업에만 적용한다.
일반 대화, 웹 검색만 필요한 요청, 로컬 리소스와 관계없는 작업에는 적용하지 않는다.
Codex CLI, IDE 에이전트, 기타 로컬 에이전트가 이 파일을 우연히 발견해도 자신의 전역 지침으로 취급하지 않는다.

## 초기화 순서

로컬 작업을 시작할 때 다음 순서로 준비한다.

1. 전역 에이전트 지침 파일이 존재하면 읽는다.
2. 사용자가 지정한 경로 또는 작업 대상에서 프로젝트 루트를 판별한다.
3. 프로젝트 루트의 로컬 지침 파일을 알려진 위치에서 확인하고 존재하는 것만 읽는다.
4. 전역 스킬 루트와 프로젝트 스킬 루트를 확인한다.
5. 스킬 발견 단계에서는 각 `SKILL.md`의 YAML frontmatter만 읽어 `name`, `description`, 필요 시 `user-invocable` 정도의 메타데이터만 확보한다.
6. 현재 작업에 필요한 최소한의 스킬만 선택한다.
7. 선택된 스킬의 `SKILL.md`만 전체 내용을 읽는다.
8. 실제 파일, 저장소, 프로세스, 도구, 빌드 상태를 확인한 뒤 작업한다.
9. 수정 후 요청에서 허용된 빌드, 상태 확인 또는 실제 실행으로 검증한다. 테스트 생성과 실행은 각각 사용자가 명시했거나 합의한 범위에 포함된 경우에만 수행한다.

같은 로컬 작업 세션에서는 부트스트랩 파일이 변경되었거나 작업 프로젝트/컨텍스트가 바뀐 경우가 아니라면 이 초기화를 불필요하게 반복하지 않는다.

## 전역 지침

다음 전역 지침 파일이 존재하면 읽는다.

- `<GLOBAL_AGENT_INSTRUCTIONS>`

전역 지침은 기본 규칙이며, 더 구체적인 프로젝트 로컬 지침과 충돌하면 프로젝트 로컬 지침을 우선한다.

## 프로젝트 루트 판별

사용자가 프로젝트 루트를 직접 지정했다면 해당 경로를 우선 사용한다.
파일 또는 하위 디렉터리만 지정했다면 상위 디렉터리를 탐색해 프로젝트 루트를 찾는다.

다음과 같은 프로젝트 마커를 사용할 수 있다.

- `.git`
- `AGENTS.md`
- `package.json`
- `*.sln`, `*.slnx`, `*.csproj`
- Unity의 경우 `Assets`, `Packages`, `ProjectSettings` 조합

하나의 마커만으로 무조건 판단하지 말고 현재 작업 맥락과 디렉터리 구조를 함께 확인한다.

## 프로젝트 지침 발견

프로젝트 루트에서 다음 알려진 위치만 확인한다.

- `<project>\AGENTS.md`
- `<project>\.agents\AGENTS.md`
- `<project>\.codex\AGENTS.md`
- `<project>\CLAUDE.md`

존재하는 파일만 읽는다.
부트스트랩 단계에서 저장소 전체를 재귀적으로 뒤져 임의의 지침 파일을 수집하지 않는다.

프로젝트 내부의 더 세부적인 하위 지침 계층이 실제로 사용되고 있다는 근거가 있거나 프로젝트 지침이 명시적으로 요구하는 경우에만 추가 탐색한다.

## 전역 스킬 발견

다음 경로가 존재하면 전역 스킬 루트로 사용한다.

- `<GLOBAL_SKILL_ROOT_1>`
- `<GLOBAL_SKILL_ROOT_2>`
- `<GLOBAL_SKILL_ROOT_3>`

각 스킬 루트의 직계 하위 디렉터리만 확인한다.
각 하위 디렉터리에 `SKILL.md`가 있으면 discovery 단계에서는 첫 YAML frontmatter만 읽는다.

`skills` 루트 밖에 보관된 템플릿, 문서, 예제 파일은 스킬이 아니므로 skill discovery 중 로드하지 않는다.

## 프로젝트 스킬 발견

프로젝트 루트에서 다음 경로가 존재하면 프로젝트 스킬 루트로 사용한다.

- `<project>\.agents\skills`
- `<project>\.codex\skills`
- `<project>\.claude\skills`

각 루트의 직계 하위 디렉터리에서 `SKILL.md`를 확인하고, 먼저 frontmatter만 읽는다.
프로젝트 전체에서 임의의 `SKILL.md`를 재귀 검색하지 않는다. `Library`, 캐시, 패키지 복사본, 빌드 산출물 등의 중복 스킬을 등록하지 않기 위해서다.

## 중복 스킬 처리

동일한 `name`의 스킬이 여러 곳에서 발견되면 지침에서 별도로 요구하지 않는 한 하나의 유효 스킬만 등록한다.

우선순위는 다음과 같다.

1. 프로젝트 로컬 스킬이 전역 스킬보다 우선한다.
2. 프로젝트 로컬 내부에서는 `.agents/skills` > `.codex/skills` > `.claude/skills` 순으로 우선한다.
3. 전역 내부에서는 위의 전역 스킬 루트 목록에서 먼저 나열된 루트의 동일 이름 스킬을 우선한다.

동일한 유효 스킬의 중복 복사본을 여러 번 전체 로드하지 않는다.

## 스킬 지연 로드

스킬 발견 단계에서는 전체 `SKILL.md` 본문을 미리 읽지 않는다.
frontmatter의 `name`, `description`을 중심으로 현재 요청과의 관련성을 판단한다.

현재 작업에 실제로 필요한 스킬만 선택하고, 선택된 스킬의 `SKILL.md`를 전체 로드한다.
스킬 내부에서 추가 규칙 파일이나 convention 문서를 읽으라고 명시하는 경우에만 해당 파일을 추가로 읽는다.

여러 영역이 동시에 필요한 작업이면 최소한의 관련 스킬 조합을 선택한다.

## 작업 원칙

로컬 상태를 추측하지 않는다.
사용자가 언급한 파일, 경로, 브랜치, 도구, 프로세스, Unity 인스턴스 등이 실제로 존재하고 접근 가능한지 확인한다.

기존 사용자 변경 사항을 임의로 덮어쓰거나 삭제하지 않는다.
작업 전 `git status` 등으로 기존 변경을 구분하고, 사용자 작업과 이번 작업의 변경을 분리한다.

수정 후에는 작업 성격과 사용자 권한에 맞는 검증을 수행한다.
예: 빌드, 린트, git diff/status, CLI 실행, Unity 연결 확인, 콘솔 오류 확인.
테스트 생성과 실행은 서로 별도 권한으로 판단하고, 사용자가 명시했거나 합의한 범위에 포함된 경우에만 수행한다.

검증하지 않은 결과를 완료 또는 정상이라고 표현하지 않는다.
